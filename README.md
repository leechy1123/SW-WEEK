# 사이트 체크 · SW WEEK 웹 취약점 진단 대시보드

**주소를 입력하고, 문제를 이해하고, 수정 전후를 비교하는 초보자용 보안 실습 프로젝트입니다.**

Python 3.10 이상과 브라우저만 있으면 됩니다. 외부 패키지, Node.js, 데이터베이스 설치, 계정 가입은 필요 없습니다. 서버 실행 후에는 인터넷 없이 실습할 수 있습니다. OWASP 공식 문서 링크를 열 때만 인터넷이 필요합니다.

## 1. 가장 빠르게 실행하기

Windows에서는 압축을 먼저 풀고 `start.bat`을 더블클릭하세요. 창에 나오는 주소를 브라우저에서 여세요.

VS Code에서는 **파일 → 폴더 열기**로 `sw-week-security-lab` 폴더를 열고 **터미널 → 새 터미널**에서 실행하세요.

```powershell
python app.py
```

Windows에서 `python`이 안 되면 다음 명령을 사용하세요.

```powershell
py -3 app.py
```

macOS/Linux는 `python3 app.py`를 사용합니다. 종료하려면 터미널에서 `Ctrl+C`를 누르세요.

| 화면 | 기본 실행 주소 |
| --- | --- |
| 진단 대시보드 | http://127.0.0.1:8000 |
| 수정 전 실습 | http://127.0.0.1:8000/lab/vulnerable |
| 수정 후 실습 | http://127.0.0.1:8000/lab/fixed |

`127.0.0.1`은 **현재 내 컴퓨터**입니다. 다른 사람은 자신의 컴퓨터에서 이 프로젝트를 실행하면 같은 주소로 실습할 수 있습니다. 이 주소는 인터넷 공유 링크가 아닙니다.

8000번 포트를 이미 사용한다면 `python app.py --port 8001`로 실행하고 http://127.0.0.1:8001 을 여세요. 대시보드의 실습 주소도 자동으로 바뀝니다.

## 2. 코딩을 몰라도 가능한 실습

1. 대시보드에서 **수정 전**을 선택합니다. 실습 URL이 자동 입력됩니다.
2. 직접 실행한 교육용 환경이라는 확인란에 체크합니다.
3. **진단 시작**을 누릅니다. 처음 배포된 코드에서는 취약점 3건이 나옵니다.
4. 각 결과를 펼쳐 **발견 위치 → 실제 응답 → 수정 방법 → 수정 코드**를 읽습니다.
5. **직접 실습해 보기**에서 다른 사람 글 보기, 상세 오류 보기, 참·거짓 검색을 눌러봅니다.
6. **수정 전후 한 번에 비교**를 누릅니다. 수정 후 버전의 검사 통과 3건과 정상 기능 유지 여부를 확인합니다.
7. **결과 저장**을 누르면 실제 응답 근거를 담은 JSON 보고서가 저장됩니다.

결과는 미리 정해진 가상 숫자가 아닙니다. 진단기가 이 앱의 실습 API에 실제 HTTP 요청을 보내 응답을 비교합니다. 단일 버전 진단은 8회, 전후 비교는 16회 요청입니다.

## 3. 세 가지 취약점 · OWASP Top 10:2025

| 분류 | 쉽게 설명하면 | 이 프로젝트에서 확인하는 것 | 수정 핵심 |
| --- | --- | --- | --- |
| A01 접근 통제 실패 | 내 열쇠로 남의 사물함도 열림 | 내 글·남의 글·비로그인 응답 비교 | 서버에서 글 주인과 현재 사용자 비교 |
| A02 보안 설정 오류 | 오류 안내에 내부 설계도까지 표시 | 정상 응답과 상세 오류의 내부 정보 노출 비교 | 상세 오류를 화면에서 숨기기 |
| A05 인젝션 | 검색어가 명령으로 실행됨 | 정상 검색과 참·거짓 조건 검색의 결과 비교 | SQL 매개변수 바인딩 |

**2025 기준**입니다. 2021의 A02는 암호화 실패, A05는 보안 설정 오류이므로 혼동하지 마세요.

수정 후의 기준: 본인 글 200 / 다른 사람 글 403 / 비로그인 401, 오류 응답 500에서 내부 경로 숨김, 정상 ‘노트’ 검색 1개 / 두 테스트 입력 0개. 응답이 예상과 다르거나 정상 기능이 깨지면 **미확인**으로 표시합니다. 요청 자체가 실패하면 **진단 실패**이며 안전하다고 표시하지 않습니다.

## 4. VS Code에서 내 손으로 고치기

`sw-week-security-lab.code-workspace`를 열어도 됩니다. 별도 확장 없이 터미널에서 실행할 수 있습니다. **Ctrl+Shift+B**를 누르면 실행 작업이 시작됩니다. F5 디버깅은 Microsoft Python / Python Debugger 확장을 설치한 경우 사용할 수 있습니다.

1. `lab.py` 상단의 `REPAIR_ACCESS = False`를 `True`로 바꿉니다.
2. 저장하고 터미널에서 Ctrl+C로 서버를 종료한 뒤 `python app.py`로 재실행합니다. 자동 재시작 기능은 없습니다.
3. 대시보드에서 **수정 전**을 다시 진단합니다. A01은 통과, A02·A05는 발견 상태가 됩니다.
4. `REPAIR_DEBUG`, `REPAIR_SQL`도 하나씩 고치고 비교합니다.
5. 세 값을 모두 `False`로 되돌리면 원래 실습 상태로 돌아갑니다.

옵션은 학습을 돕는 장치입니다. 실제 해결 코드가 궁금하면 아래 함수의 `if version == "fixed" or REPAIR_...` 블록을 읽어보세요. 수정 후 버전은 옵션에 관계없이 수정 로직을 사용합니다. 데이터는 요청마다 메모리에 만들어지므로 재설정할 DB가 없습니다.

## 5. 파일 구성과 읽는 순서

```text
sw-week-security-lab/
├── app.py                  # 웹 서버: URL에 맞는 함수 연결
├── lab.py                  # 가장 먼저 읽기: 3개 취약 기능과 수정 코드
├── scanner.py              # URL 검증 → 요청 → 응답 비교
├── lessons.py              # 한국어 설명, 수정 예시, 출처
├── static/
│   ├── index.html          # 대시보드 구조
│   ├── style.css           # 화면 디자인과 모바일 레이아웃
│   ├── app.js              # 진단 버튼, 결과 표시, 파일 저장
│   ├── lab.html            # 직접 조작하는 실습 화면
│   └── lab.js              # 실습 버튼과 API 연결
├── tests/test_project.py   # 실제 로컬 HTTP 통합 테스트
├── docs/BEGINNER_GUIDE.md   # 15분 수업 / 발표 순서와 용어 설명
├── .vscode/                # 실행·디버깅 설정
├── start.bat               # Windows 간편 실행
└── sw-week-security-lab.code-workspace
```

작동 흐름: `브라우저 → POST /api/scan → scanner.py → GET /lab/... → lab.py → 응답 비교 → 브라우저`

정적 HTML을 파일 탐색기에서 직접 열거나 VS Code Live Server로 열면 Python API가 연결되지 않습니다. 반드시 `python app.py`가 출력한 주소를 사용하세요.

## 6. 테스트

```powershell
python -m unittest discover -s tests -v
```

테스트는 임시 로컬 포트에서 서버를 실행합니다. 외부 네트워크는 사용하지 않습니다. 취약·수정 버전 실제 응답, 정상 기능 유지, URL 제한, 교차 출처 차단, 수정 옵션, 실패 시 미확인을 검사합니다.

## 7. 진단 범위와 구현 선택

- 사용자 제공 PDF의 **실습 URL 검사·응답 근거·원인과 코드·수정 전후 비교** 흐름을 기반으로 했습니다.
- `sw-week-main`의 **밝은 배경, URL 입력, 결과 카드, 펼치는 설명, JSON 저장** 구성을 참고했습니다. 학습 내용에 맞게 화면을 새로 구성했습니다.
- 기존 Streamlit 의존성을 없애 Python 표준 라이브러리 + HTML/CSS/JavaScript로 작성했습니다. 프레임워크 학습과 패키지 설치 부담을 줄이기 위한 선택입니다.
- **등록된 두 실습 URL만 진단**합니다. 임의의 외부 웹사이트, 사설 IP, 다른 포트, 임의 경로에는 요청하지 않습니다. 외부 서비스의 로그인 권한이나 SQL 인젝션을 자동 진단하는 범용 스캐너는 아닙니다.
- A01 전체, A02 전체, A05 전체를 검사하는 것은 아닙니다. 각각의 대표 사례 1개를 학습합니다. 통과는 사이트 전체 안전성 보장이 아닙니다.
- 학습 편의상 하드코딩된 `demo-alice`, `demo-bob` 세션을 사용합니다. 실제 인증 시스템이 아니며 운영 환경에서 재사용하면 안 됩니다.
- SQLite DB는 매 요청마다 메모리에 생성하며 가상 데이터만 사용합니다. 테스트 입력은 조회만 수행합니다.
- 진단에는 상태와 응답 내용, 정상 기능을 함께 사용합니다. A02의 500은 의도적인 오류이며 숫자 자체가 취약점은 아닙니다.
- 서버는 127.0.0.1에만 바인딩하고 Host·Origin 검사, 동시 진단 제한, 입력 크기 제한을 둡니다. 외부 서버로 연결하거나 리디렉션을 따라가지 않습니다.
- 보고서의 A02 수정 전 근거에는 **로컬 코드 파일 경로**가 들어갈 수 있습니다. 공유 전에 경로의 사용자명 등을 확인하세요.
- 이 앱은 로컬 교육용입니다. 취약 실습 API와 Python http.server를 인터넷에 공개하거나 바인딩 주소를 0.0.0.0으로 바꾸지 마세요. 다른 사람에게는 프로젝트 ZIP을 전달해 각자 로컬에서 실행하도록 안내하세요.
